# Design review 1: passkey sign-in (sign-in card + Settings Passkeys)

VERDICT: PASS WITH FIXES (no MAJOR on the card; one MAJOR on the remove flow)

| # | Sev | Where | What | Smallest fix |
|---|-----|-------|------|--------------|
| 1 | MAJOR | passkeys-section.tsx remove() | "Confirm remove" never resets: no timeout, no blur, no Cancel. Not confirming leaves the row armed forever, and a second row can be armed too, so one stray tap later deletes a passkey. Armed state also looks like "Remove" (same danger outline, text only; see screenshot). | Reset confirmId on blur and after about 5 s; and make the armed state visibly different (e.g. filled bad tint plus "Confirm remove" text), or add a small "Cancel" ghost button beside it. |
| 2 | MINOR | add error (settings shot) | Duplicate-device error shows the raw library text ("The user attempted to register an authenticator that contains one of the credentials already registered with the relying party."). Unreadable to a non-technical owner. | Map the 409/duplicate text to "This device already has a passkey here." |
| 3 | MINOR | sign-in.tsx error | Passkey failures render under the token field with aria-invalid on it and above both buttons, so a passkey error appears to blame the token and sits away from the button pressed. | Show passkey errors in a role=alert line directly under the passkey button; keep aria-invalid for token errors only. |
| 4 | MINOR | sign-in.tsx | Hierarchy is right: lime primary "Sign in", grey secondary pill below, token field autofocused and first (393 and 1280 shots). But the intro line still says only "Enter the access token..." and nothing says the two are alternatives. | Optional: change the intro to "Enter your access token, or use a passkey." Do not add a divider or "or" row. |
| 5 | MINOR | both | Button is h-10 (40 px) on the phone, sm remove is h-9 (36 px). Below the 44 px phone target in design.md section 12; the existing Sign in button is the same 40, so it is a system gap, not new. Remove (36 px) is the weakest. | Remove: use size md on the phone (h-11 via className) so a tired thumb does not hit the neighbour. Fix Button globally later. |
| 6 | MINOR | empty list | "No passkeys added yet." is bare. When passkeys are off the form is hidden too, so it is a dead end; design.md says empty states say what will appear and when. | "No passkeys yet. Add one below and it will appear here." (and "Passkeys are switched off on the server." when disabled). |
| 7 | MINOR | row meta | Date uses toLocaleDateString (10/14/2026), ambiguous and not the shared formatter style; the "Last used" side uses ago(). | Use the shared formatter from @nflpi/shared for the date. |
| 8 | MINOR | add form | Name field has no hint that the name only labels the device, and the 64 limit is silent. | label: "Passkey name (optional)" plus text-xs subtle hint "For example, Owner iPhone." |

Checked and fine: spacing uses only scale values (space-y-4, gap-2/3, p-3, pt-4); no new colour or component (Button danger/secondary, Notice bad, Section, input class copied from the token field, 24 radius bezel); error is a role=alert Notice at the bottom of the section; no modal for confirm, matching section 9; input is 44 px and 16 px type on the phone (no iOS zoom); row text wraps (min-w-0, break-words, flex-wrap) and the add row shrinks the input (flex-1 min-w-0), so 320 px should fit; sign-in buttons are disabled against each other while busy; Remove disabled while another row is removing.

Could not verify: phone Settings render at 320 to 393 px (no shot; judged from code only); focus ring appearance (relies on a global rule I did not open; design.md says 2px accent outline); the loading and list-error states; the passkey error wording on screen at 393 px; real Face ID prompt behaviour.
