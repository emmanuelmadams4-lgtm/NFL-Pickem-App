## How this was checked

* Each repository was cloned shallow (`git clone --depth 1`) into a scratch folder outside this repository on 2026-10-13, and **read only**. Nothing in any of them was run, imported, installed or built.
* One reader subagent per repository read the files and reported with file and line. Their full reports are in `docs/gauntlet/logs/step-18a-evidence/repos/`.
* The coordinator checked every **commit** and every **license** below against the clone itself (`git log -1`, the license file's first lines, the package metadata), and spot-checked the claims marked ✔ with `grep` on the clone. A claim without ✔ is the reader's, cited in its report, not re-checked.
* "Author's claim" means a number the repository states about itself. None of those numbers was reproduced here.
* License rule (D68): no license file means **no license: ideas only**. Nothing is copied from such a repository.

## nflreadpy in detail

**What it would replace.** In `backend/nflpi/ingestion/nflverse.py`, only the download of nflverse files: `fetch_csv` (lines 57-61) and the retry loop `_fetch` (lines 64-78) for these requests:

| The app asks for | Called from | nflreadpy function |
|---|---|---|
| `schedules/games.csv` | `ingestion/service.py:120`, `jobs.py:67` | `load_schedules` |
| `teams/teams_colors_logos.csv` | `ingestion/service.py:169` | `load_teams` |
| `injuries/injuries_<season>.csv` | `ingestion/service.py:194` | `load_injuries` |
| `snap_counts/…`, `stats_player/…`, `players/players.csv` | `ingestion/service.py:253-255` | `load_snap_counts`, `load_player_stats`, `load_players` |
| `stats_team/stats_team_week_<season>.csv`, `pbp/play_by_play_<season>.csv.gz` | bench scripts in `docs/gauntlet/logs/step-14*-evidence/` | `load_team_stats`, `load_pbp` |

**What it would not replace.** The two ESPN calls (`fetch_json`, `fetch_head_coaches`), every parser (`parse_games`, `parse_teams`, `parse_injuries`, the star parsers), the franchise mapping, the kickoff-to-UTC conversion, the Open-Meteo weather adapter, and the live odds adapters. The parsers read text rows where a missing value is `""` or `"NA"`; nflreadpy returns typed Polars frames with nulls, so every parser would need an adapter or a rewrite, and their tests with it.

**What it costs.** Three new packages (polars, platformdirs, tqdm; the app already has requests, pydantic and pydantic-settings). Polars is one large compiled wheel, and the Docker image grows by it. The app's own download has a retry loop and a configurable base address (`config.py:21`); nflreadpy's downloader has no retry. `load_schedules` also blanks unusual `roof` values, a small behaviour change.

**Is it worth it now?** No. The app already downloads the same files from the same nflverse release addresses in about 20 lines that work and are tested. Swapping today buys nothing the owner can see and puts three packages and a parser rewrite at risk.

**When it becomes worth it.** When step 18e loads play-by-play, weekly rosters or depth charts. Those files are large (a season of play-by-play is tens of megabytes as text), Parquet with a file cache is the right tool for them, and nflreadpy already knows every file name. Then: add it for the **new** feeds only, keep the existing parsers on the existing download, and follow D68 for the dependency (license is MIT and checked here; Dwight reviews; the integrator grants the `pyproject.toml` seam).
